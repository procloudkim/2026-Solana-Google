# x402 v2: HTTP 결제 요구와 정산 흐름

확인일: 2026-08-03

이 문서는 x402를 사용할 때 구현해야 할 wire contract와, 현재 Mandate Pool이 x402라고 주장할 수 없는 이유를 설명한다.

## v2 결제 흐름

```text
client request
  -> 402 + PAYMENT-REQUIRED
  -> wallet creates signed payment payload
  -> retry + PAYMENT-SIGNATURE
  -> seller/facilitator verify and settle
  -> 200 resource + PAYMENT-RESPONSE
```

x402는 HTTP 요청과 programmatic payment를 연결한다. facilitator는 선택 사항이며 seller가 직접 검증·정산할 수도 있다. 어떤 경로든 resource를 반환하기 전에 payment payload를 검증하고 settlement 결과를 처리해야 한다.

## v1에서 v2로 바뀐 핵심

| 영역 | v1 | v2 구현 기준 |
|---|---|---|
| client payment header | `X-PAYMENT` | `PAYMENT-SIGNATURE` |
| server response header | `X-PAYMENT-RESPONSE` | `PAYMENT-RESPONSE` |
| requirement 전달 | 주로 response body | `PAYMENT-REQUIRED` |
| network ID | `solana-devnet` 같은 문자열 | CAIP-2 `solana:devnet` |
| version field | `x402Version: 1` | `x402Version: 2` |
| Solana package | legacy 통합 | `@x402/svm` 또는 해당 언어의 SVM support |

공식 migration guide는 신규 구현에서 v2를 기본으로 사용하라고 안내한다. 오래된 슬라이드의 `X-PAYMENT`를 복사하지 않는다.

## 계정·키·facilitator 경계

x402는 stateless하고 별도 session·authentication 의존을 줄이는 것을 목표로 하지만, 결제 payload를 만들 wallet과 signature는 필요하다. facilitator 선택에 따라 운영 인증도 달라진다.

- CDP buyer quickstart는 CDP account·API keys와 wallet 구성을 전제로 한다.
- self-managed wallet과 독립 facilitator를 선택할 수 있지만 key custody·network funding 책임은 사라지지 않는다.
- 공식 migration guide의 CDP facilitator는 Solana와 Solana Devnet을 지원하고, 공개 `x402.org` facilitator는 testnet-only 경로로 Solana Devnet을 포함한다고 안내한다.

따라서 `x402는 API key가 전혀 필요 없다`는 보편 명제는 정확하지 않다. protocol의 stateless 목표와 특정 facilitator의 인증을 분리해 설명한다.

## Mandate Pool과의 관계

Mandate Pool v0에는 seller의 HTTP 402 challenge, v2 payment headers, facilitator settlement가 없다. 세 buyer가 한 Solana transaction의 서로 다른 transfer에 서명하는 custom settlement이므로 x402 구현으로 소개하지 않는다.

후속 x402 adapter는 다음 조건이 있을 때 의미가 있다.

- 외부 seller가 HTTP resource와 정확한 price requirement를 반환한다.
- 단일 payer 또는 명확한 sponsored payment model이 있다.
- quote와 `network/asset/payTo/amount/resource/method/body hash/expiry`를 서명에 묶는다.
- payment receipt뿐 아니라 구매한 resource가 실제 후속 agent 행동에 사용된다.

## 구현 체크리스트

1. SDK/package와 x402 version을 고정한다.
2. CAIP-2 network, scheme, asset, recipient, max amount를 allowlist한다.
3. 402 response와 provider content를 untrusted input으로 검증한다.
4. idempotency key와 settlement state를 durable store에 기록한다.
5. response loss 뒤 재결제하지 않도록 기존 payment를 reconcile한다.
6. trace에 402 requirement, signed payload hash, settlement response, on-chain signature, resource result를 연결한다.

이 문서는 wire contract를 정리한 것이며 특정 facilitator의 가용성, 현재 계정 자격 증명, 실제 Devnet settlement 성공을 보장하지 않는다.
