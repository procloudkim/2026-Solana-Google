# 모듈: 에이전트 프로토콜 지도

근거: [에이전트·상거래 프로토콜 추출본](../sources/agent-protocols.md), [x402](../sources/x402.md), [MPP](../sources/mpp.md)

## 층별 지도

```text
사용자 의도와 권한
  AP2 mandates / authorization
          |
상거래 발견·주문·checkout
  UCP / ACP
          |
에이전트 협업            도구·데이터 연결
  A2A                    MCP
          \              /
           결제 요구·협상
           x402 v2 / MPP
                  |
           지갑 실행·정산
           pay.sh / Solana
```

이 도식은 조합 가능성을 보여 주는 책임 지도다. 특정 프로토콜이 반드시 다른 프로토콜 위에 구현되어야 한다는 규격 의존 그래프는 아니다.

## 선택 질문

| 질문 | 우선 확인할 규격 |
|---|---|
| 다른 에이전트에게 작업을 넘기고 상태를 받는가? | A2A |
| 모델이 외부 도구·리소스·prompt를 표준 방식으로 쓰는가? | MCP |
| 사용자가 에이전트에게 구매 권한을 어떻게 위임했는가? | AP2 |
| 상품·checkout·order 상태를 여러 상거래 참여자가 공유하는가? | UCP 또는 ACP |
| HTTP 리소스 접근 전에 402 결제를 요구하는가? | x402 v2 |
| 일회성뿐 아니라 session·반복 결제를 협상하는가? | MPP |

## 구현 규칙

- 프로토콜 이름만 나열하지 말고 각 메시지가 해결하는 책임을 적는다.
- 버전 없는 슬라이드보다 구현 시점의 공식 schema/spec URL을 잠근다.
- AP2 샘플의 ADK/Gemini 사용을 AP2의 필수 런타임으로 오해하지 않는다.
- x402의 프로토콜 무계정 목표와 facilitator API 인증을 분리한다.
